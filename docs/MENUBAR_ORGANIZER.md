# 菜单栏收纳

## 原生展开（新用户默认）

1. 在侧边栏选择 **菜单栏收纳**，点 **启用菜单栏收纳**。插件增加控制图标及 `│` 分隔符，先保持展开；已有启用选择会继续保存，但每次启动不自动收起。
2. 把控制图标留在分隔符右侧，点 **排列原生图标…**，在原生菜单栏按住 **⌘** 把待收纳图标拖到分隔符左侧。此按钮只展开并显示说明，不代替用户拖动。
3. 点击控制图标或 **收起原生图标**，也可按 **⌃⌥⌘H** 切换。展开后直接点击真实图标；普通点击不截图、不调用 AX、不移动图标，不需要屏幕录制或辅助功能权限。
4. 只在显式点击或快捷键时收起，不设置自动收起定时器或外点监听；操作第三方菜单期间保持展开。右键控制图标可排列、打开可选面板或回到工具箱。
5. **⌃⌥⌘R** 紧急展开；主界面及工具箱托盘菜单也能展开。停用或退出时先展开，停用随后移除自家状态图标；显示器变化会关闭浮窗、清空缓存并取消在途操作，已确认收起的状态保留。

首次启用会沿用原有的自家图标位置兼容处理，只写本应用的状态图标位置键，不更改其他应用偏好；关闭后保留原工具箱位置恢复逻辑。菜单栏物理容量有限，位置提示不能保证图标不被应用菜单遮住。

## 可选图标面板及高级布局编辑

- 在「普通点击」中选择 **图标面板**，或主动点击 **高级 · 图标面板与布局编辑 → 打开 / 关闭图标面板**。旧用户（已有 `optedIn` 设置，包括关闭选择）保留面板点击模式；新增 `presentationMode` 保存显式选择，原有 `optedIn`、`visibleLimit` 不覆盖。新用户首次启用后再启动仍保持原生模式。
- 面板使用锚定控制图标的原生浮窗，没有标题栏或固定大块页面；44 点图标、56 点点击区域；宽度随数量变化（最多 510 点），每区最多两行，更多图标用上一页 / 下一页切换，无横向滚动条，无常驻图标时隐藏第二排。外点、Esc、失焦或再次点按钮会关闭浮窗并清空缓存，已确认收起的原生图标保持隐藏；采集中取消或失败才恢复展开，鼠标/本地 Esc 监听只在该次浮窗打开期间存在；再次点击控制图标只关闭浮窗一次，不立即重开或自动展开原生区。
- 浮窗中的 **打开工具箱** 经宿主回调打开主窗口，自动选择 **菜单栏收纳** 并展开 **高级 · 图标面板与布局编辑**。勾选 **允许浮窗调整真实图标（本次运行）** 才能在浮窗里拖放；**⌘ 排列** 只展开原生图标供手动排列。
- 面板需要屏幕录制权限。仅 **权限与帮助 → 屏幕录制权限 / 辅助功能权限** 会请求对应授权；缺少权限时保持展开并提示原因。系统授权可能需要重启；临时签名每次构建可能改变代码身份，原授权不一定适用。稳定签名方式见 README。
- 打开面板先展开并等待 350 毫秒让菜单栏重排，读取分隔符左侧图标及可见区的缩略图，确认隐藏区全部捕获、顺序未变、收起布局完成且控制图标可见后才显示面板。采集前后顺序变化时只重试一次；仍变化则保持展开并显示帮助浮窗。任一隐藏区截图失败则保持展开；常驻区从分隔符右边界开始，包含分隔符与控制按钮之间的图标，不把控制按钮当分区边界；仅略过本应用状态项（浮窗已有工具箱入口）。常驻缩略图不可读取时保留对应 ID 和占位提示，不能静默丢掉第 7 个或其他项。面板只显示捕获到的候选图标，不能保证恢复离屏或刘海下的图标。
- 浮窗的 **编辑** 按钮只在本次运行开启调整模式；选择图标后用 **移到常驻区 / 移到收纳区、前移、后移** 操作，无需用户在原生菜单栏拖到该图标。缺少 AX 权限只显示帮助，不主动请求；移动仍由现有模拟 ⌘ 手势实现并验证结果，不是公共跨应用重排 API。刘海 / 离屏起点或目标在发送 mouse-down 前拒绝，保持展开并说明限制；不能承诺直接移动刘海后或系统未暴露的图标。
- 要从面板跨区拖放/同区排序，需明确勾选 **允许浮窗调整真实图标（本次运行）**。默认关闭，重启、停用、切换模式后关闭；打开面板不会顺带申请 AX 或开启编辑。移动成功重新采集，失败保持展开。用户主动点击 **主动按数量整理** 才依次尝试移动超出 `visibleLimit` 的图标；普通控制点击不会调用数量整理。
- 浏览态单击图标会关闭浮窗及其事件监听、展开原生菜单栏，然后重新核对同一窗口 ID / 所属进程、可见安全区及布局稳定性。点击前再次通过系统 AX 命中查询核对前景元素的所属进程与按钮几何，避免点击覆盖在图标上的应用菜单或其他窗口；仅对唯一、当前可见的原状态窗口发送无修饰键的普通点击；不依赖第三方可能无法完成的 AXPress。刘海下、离屏、窗口已退出、重叠或布局变化时拒绝点击并显示原因；不使用截图中的旧坐标。拖动手势只附加在编辑态，浏览态保留普通按钮手势；编辑态单击只选择；原图标调用后保持展开，不自动收起或激活工具箱打断第三方菜单。
- 缩略图保留采集时的原始颜色。展开、关闭浮窗、打开工具箱、切换模式或停用都清除缓存和取消后续采集。已被系统受理的在途截图可能完成，结果会因 generation 不匹配而丢弃，不能承诺系统请求瞬间结束；图片仅在该任务存活期间暂存内存，不写文件、不上传、不采集音频。

## 实现与失败恢复

- 只支持现有 macOS 14–26 范围，低于 14 或 27 及以上维持原有拒绝启用的保护，不宣称已验证新系统。
- 原生收起仍采用自家分隔符撑宽，让左侧图标溢出；不是公开的跨应用重排 API。长度按最宽屏幕的两倍、最多 10000 点计算；多屏、刘海及前台应用菜单宽度会限制展开后的原生显示容量。
- `MenuBarVisibility` 是无 AppKit 副作用的状态机：`disabled → expanded → collapsing → collapsed`。收起后延迟检查自家分隔符确实变宽、控制按钮的屏幕矩形仍完全位于当前屏幕及刘海安全区（不是高度可能超出安全区的背后状态栏窗口）；无法确认则恢复展开。快速再次点击、紧急展开、显示器变化或停用会换 generation，使旧确认不能重新收起。几何检查不能证明所有第三方图标都无遮挡。
- `MenuBarGallerySession` 独立持有捕获 generation、捕获中标记及两排内存图片；`MenuBarCapture` 保序、最多四路并发，支持 0–3 个图标，异常不返回半套隐藏区。插件负责 AppKit、权限检查、截图及可选 AX/拖动效果；新路径未引入第三方依赖。
- 高级合成 ⌘-拖动不是任意移动其他应用图标的公共 API，第三方可能拒绝。只处理当前可见且定位安全的图标；有限次数、逐个确认，取消仍发 mouse-up 结束已经开始的手势，不后台持续重排。移动期间的 generation 防止取消后继续发起后续移动。
- 强制结束或崩溃不能执行正常退出钩子；自家分隔符随进程移除，第三方排序仍由 macOS 保存。停止收纳不会主动重新排序第三方图标。

## 验证范围与人工矩阵

安全离线检查（不启动应用、不捕获用户屏幕）：

```sh
swift test --filter 'MenuBarVisibilityTests|MenuBarOrganizerTests|MenuBarIconActivationTests'
swift build -c release
```

测试覆盖旧配置迁移、新用户首轮启用保存、迟到确认、停用再启用、失败展开、负坐标多屏与刘海安全区、缓存清空、0–7 个模拟截图的顺序及并发上限、取消不补发、截图错误不返回部分结果、6/7/17/40 个常驻候选的身份保留与分页覆盖、完成收起后关闭浮窗不反向展开；自动测试不替代实机显隐核验。完整宿主测试及 UI 脚本可能创建窗口或操作测试电源断言，需要单独安排。

| 人工场景 | 预期 | 本轮状态 |
| --- | --- | --- |
| 未授权 AX/录屏、原生模式日常点击 | 可展开/收起，无权限弹窗及模拟移动 | 待实际菜单栏验证 |
| 小量 1–3 / 多量隐藏图标、截图失败或撤销授权 | 面板完整才收起；失败展开，缓存清除 | 模拟路径通过，真实权限待验 |
| 刘海屏、长应用菜单、负坐标多屏、断开外屏 | 控制按钮不安全就保持展开；屏幕变化取消浮窗及在途操作 | 纯几何通过；本机刘海屏＋负坐标外屏已实点验证，37 点窗口/32 点安全区误判已修复；断屏与长菜单待验 |
| 快速连点、采集中切模式、关闭面板/插件、正常退出 | 无迟到再收起或重开面板；完成收起后关浮窗保持隐藏，未完成/停用/退出恢复展开 | 状态/取消单测通过；实点重复控制、外点和 Esc 均保持收纳区隐藏，打开工具箱已验，其他生命周期待验 |
| 浏览态调用原功能、编辑态选择、第三方菜单保持打开 | 调用后展开，不自动收起或打断原菜单；编辑态只选择 | 已实点输入法收纳图标及控制中心常驻图标，并核对原窗口保持打开、编辑态不调用；刘海目标明确拒绝，其他第三方应用待验 |
| 明确开启高级编辑及主动数量整理 | 才尝试 AX/⌘-拖动；拒绝/取消后保持展开 | 本轮未执行任何真实拖动 |
| 已有 opt-in 与数量设置升级/降级 | 升级保留模式与旧键；新增键旧版忽略 | 隔离偏好单测通过 |
| 7 个常驻应用与原生显隐 | 第 7 项不丢失；关闭浮窗不撤销原生收起 | 本机逐 ID 核验原有 7 项均在浮窗及原生常驻区；收纳原生窗口离开可见区，显式展开/收起四次核验通过；数量 6/7/17/40 分页为模拟测试 |
